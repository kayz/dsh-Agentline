# Studio 20261106 — 用户决策

状态：已确认
日期：2026-11-06
对应问题：`questions.md`

## Q1 控制面边界

**决定：A。**

- 在 `orchestrator/` 下新增与 `flow.mjs` 平级的 Studio / Blueprint 控制面模块；
- 通过 `agentline studio|blueprint` 公开；
- `flow.mjs` 保持单任务 Build 内核，零侵入；
- 插件只做无状态投影、输入收集和公开 CLI 调用，不写 `.collab/**`，不做第二套 orchestrator。

## Q2 版本顺序

**决定：先做完整 Blueprint，再做工作轮次切分。**

不采用“先做三阶段只读外壳”的路线。Blueprint 必须首先完成：

- 三阶段的界面与用户体验设计；
- 对话框内的 slash 命令设计；
- 插件的监控内容设计；
- 模型管理/配置界面；
- 控制面、插件、Build 内核的接口与状态边界；
- 错误、gate、审批、轮次规则；
- 完成后再把实现切成工作轮次。

## Q3 模型维护

**决定：自动/手动维护结合，手工指定兜底，并提供配置界面。**

- 支持自动发现和手动登记模型；
- 根据当前行业公认信息给出模型建议，但不把“自动建议”当成授权；
- 角色选择以手工指定为最终兜底；
- 配置界面必须能查看：模型来源、厂商、档位、能力、可调用性、最近验证时间；
- 模型变化/下线/新版本时，不静默替换，进入待确认或 blocked；
- 具体模型列表和档位由 Blueprint 设计，不在本决策中写死。

## Q4 模型验证

**决定：模型指定后先做短上下文测试。**

- 角色分配完成后、正式阶段开始前，执行短上下文 probe；
- 记录 `model_requested`、`model_resolved`、provider、CLI 版本、耗时、错误；
- probe 失败不得静默降级，按错误规则处理；
- probe 结果作为模型可调用性和实际身份的证据。

## Q5 轮次与错误

**决定：区分业务不收敛和可逆基础设施问题。**

- 如果是模型限制、断网、429 等可逆问题：通过轮换模型/重试继续，不记为业务硬停；
- 如果是三轮后 dev 和 review 仍达不成业务共识：交给用户判断；
- “非业务问题造成的轮次错误”不记录为硬停，但必须记录尝试、模型、错误和恢复动作；
- 业务分歧的轮次上限和用户裁决必须落盘；
- 不允许用自动重试掩盖业务分歧。

## Q6 讨论记录 Git 留存

**决定：A。**

- 定稿契约、状态、run/verdict 进入 git；
- `logs/`、`rounds/`、`handoff/` 等过程原始记录外置或 gitignore；
- 本地保留哈希索引，供审计和恢复校验；
- 不把完整讨论日志、用户回答和代码上下文默认推进产品仓库历史。

## D1：K1 授权

**决定：A，授权 K1。**

- 允许在 `flow.mjs` 增加单步入口 `runStep`，由 Build Supervisor 驱动循环；
- 这是对 Q1“flow 零侵入”的有限例外；
- `runFlow` 和 `exec.mjs` 的既有语义不得改变；
- K1 必须补齐崩溃恢复、证据先归档、amendment 纪元幂等；
- 授权 K1 不等于 B1 自动关闭，仍需通过契约收口。

## D2：身份未验证策略

**决定：允许人工登记。**

- 默认要求实际模型身份证据；
- 可以人工登记固定版本例外，但必须持续显示 `unverified`；
- 例外需记录操作者、时间、原因、版本和适用范围；
- 不得把例外显示成“身份已验证”，也不得据此宣称隔离已验证；
- 自动发现结果仍不能自动进入 top allowlist。

## D3：三轮后人工追加

**决定：允许显式追加。**

- 三轮后进入 `awaiting_user`；
- 用户每次只能显式授权追加一轮；
- 每次追加记录授权人、时间、原因、新增预算和 `deviations`；
- 不接受“自动延长”或“未通过评审直接接受”。

## D4：本机人工授权信任边界

**决定：接受本机 CLI 作为受信任的审批入口。**

- 明确这是“本机用户账户”的信任约定，不是机器对“操作者是人”的证明；
- Host 签名只能提高伪造门槛；
- 审批记录必须包含 channel、调用者、原文、时间和内容哈希；
- 任何自动化代理仍不得替用户批准。

## S1：旧输入与旧执行者范围

**决定：S1-1=A，S1-2=A。**

- 运行期间不支持 L-foreign 外部 CLI 并发写输入；
- 新版输入命令和 runStep 通过输入锁互斥；
- 不修改 `inputs.mjs` 的 append-only 格式；
- 可证明的旧执行者仍保持非零/`unknown`，直到终止证明；
- “从未被观测、且没有残留证据的旧 L-foreign 执行者”排除出 drain 保证；
- 该排除必须在文档中明确写出，不能默认为“没有运行”。
